App purpose: Customers receive a timed email reminder about their abandoned cart after your configured delay, increasing the chance they return to complete the purchase.
App category: backend_admin
Trigger types: cron

Quality brief — what makes a good version of this app:
The app must identify genuinely abandoned carts (items added but checkout not completed) and avoid re-sending to the same customer. It should handle edge cases like carts cleared before the delay expires, customers who already purchased, and duplicate email prevention. The admin page must make the delay setting obvious and show delivery metrics so the merchant can judge effectiveness. Email should link directly back to the cart.

UX expectations for this admin panel:
The merchant dashboard must prominently display the abandonment delay setting (in hours) with a clear save action, and show a delivery metrics table (total sent, open-rate proxy via clicks if available, carts recovered) so the merchant can judge campaign effectiveness at a glance. Recent reminder log with cart value and send status should be paginated below the metrics summary.

Column enum vocabulary — the handler stores ONLY these literal values in each column:
  abandonment_reminders.status: ["pending", "sent", "failed", "skipped"]
When rendering filter dropdowns, status badges, or any UI that branches on one of these column values, use ONLY values from the matching list. Do NOT invent additional values (e.g. a 'converted' filter when the column enum is ['pending','sent','failed']) — those render dead options the merchant cannot act on.

Backend limitations the admin UI should surface:
  - No batch write API for sending abandonment reminder emails — each eligible cart requires an individual email send call: Pre-fetch all eligible abandoned checkouts from Shopify in a single bulk read before the loop; per-item email send calls inside the loop are unavoidable for this resource type
  - Shopify does not expose whether a customer completed a purchase after abandoning a checkout in the abandonedCheckouts payload itself: Use shopify_graphql to query orders filtered by customer email and created_at >= cart updated_at during the bulk pre-fetch phase; results are indexed by email before the loop begins so no per-item API calls are needed
