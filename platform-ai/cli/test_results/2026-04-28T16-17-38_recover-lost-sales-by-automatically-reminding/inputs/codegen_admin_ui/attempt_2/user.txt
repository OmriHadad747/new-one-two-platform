App purpose: Recover lost sales by automatically reminding customers about their abandoned carts after a configurable delay.
App category: backend_admin
Trigger types: cron

Quality brief — what makes a good version of this app:
A good version of this app correctly identifies when a cart has been idle for the merchant's chosen duration, avoids sending duplicate reminders to the same customer, and provides a clear admin view of which reminders went out. Handle edge cases: don't email customers who returned and completed checkout, respect customer email preferences if available, and ensure the reminder email is compelling without being spammy. The admin page should show sent reminders with timestamps so the merchant can spot trends and measure impact.

UX expectations for this admin panel:
The dashboard should lead with a real-time reminder log showing recipient, cart value, sent timestamp, and delivery status so merchants can immediately gauge recovery impact. Settings (delay, enable/disable toggle) should be prominent but secondary. Pagination and date filtering on the log are essential once volume grows.

Column enum vocabulary — the handler stores ONLY these literal values in each column:
  abandoned_carts.reminder_status: ["pending", "sent", "skipped", "converted", "ineligible"]
  reminder_log.delivery_status: ["sent", "failed"]
When rendering filter dropdowns, status badges, or any UI that branches on one of these column values, use ONLY values from the matching list. Do NOT invent additional values (e.g. a 'converted' filter when the column enum is ['pending','sent','failed']) — those render dead options the merchant cannot act on.

Backend limitations the admin UI should surface:
  - Shopify REST/GraphQL does not expose an abandoned checkouts feed with idle-since timestamps in a way that distinguishes 'still active' from 'truly abandoned' at the per-cart level: Use the Admin GraphQL abandonedCheckouts connection (sorted by updatedAt) combined with a DB snapshot of last_seen_at per cart; the cron computes idle duration as now() minus last_seen_at stored on each tracked cart row, avoiding reliance on Shopify's own abandonment classification
  - No batch mutation API exists for sending reminder emails — each customer requires an individual platform.email.send call: Pre-fetch all eligible abandoned cart data in a single bulk GraphQL read before the loop; per-item email sends inside the loop are unavoidable for this resource type
