REVIEWER FINDINGS — apply each finding's fix to the relevant section of
the prior plan; leave everything else untouched.

- [important] persistence[3].columns[1]: "points_per_dollar": role is set to "ratio", but the spec defines ratio exclusively as a fractional value bounded between 0 and 1. A points-per-dollar earn rate (e.g. 10 points per dollar spent) is a whole-number multiplier that routinely exceeds 1. The same incorrect kind propagates into externalContracts[5].responseShape and externalContracts[6].requestShape/responseShape. The LLD will select a fractional 0–1 storage type and may silently clamp or reject any configured value above 1. Fix: Change the role of "points_per_dollar" in the persistence table to "count" (and update the matching externalContracts request/response shape kinds to "count") to correctly signal that this is a whole-number multiplier with no upper bound of 1.
- [important] capabilities[6]: "record-redemption" declares usesWorkflow: true, but per spec usesWorkflow must be false on initial-state inserts — it applies only to capabilities that own subsequent status transitions. record-redemption inserts a redemption row at a fixed initial status and never transitions it; cancel-redemption owns the transition. Marking it true will cause the LLD to generate transition-handling scaffolding (guard checks, allowed-transition logic) for a plain insert operation. Fix: Set usesWorkflow to false on record-redemption; usesWorkflow: true already correctly sits on cancel-redemption, which owns the status lifecycle.
- [important] edgeCases[5]: The edge case states "a reconciliation note must exist in the redemption record" for abandoned-cart redemptions, but the point_redemptions table has no column of role text or flag to store such a note, and there is no schedule trigger or capability declared to detect or flag stale active redemptions. The LLD has no backing persistence column or job to implement this requirement — it is an orphan promise that cannot be built from the current plan. Fix: Either add a nullable text column (e.g. "audit_note") to point_redemptions and a schedule trigger with a reconciliation capability that flags active redemptions on carts that have expired, or rewrite the edge case to describe only what the current plan can actually implement (e.g. the merchant can identify abandoned redemptions by querying active-status rows with old updated_at timestamps via the admin balance view).
